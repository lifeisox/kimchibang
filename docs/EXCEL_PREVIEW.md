# 엑셀 미리보기 사용 안내

선생님이 직접 DB 작업이나 코딩을 하실 필요는 없습니다. 이 단계는 실제 자료를 저장하기 전에 어떤 자료가 있으며 무엇을 확인해야 하는지 보여주는 단계입니다.

## 화면 사용 순서

1. **엑셀 미리보기 → 분석 요약**에서 고객 수, 주문 후보 수, 금액이 다른 행 수를 확인합니다. 최초 첨부하신 엑셀은 이미 분석해 두었습니다.
2. **확인 필요**에서 사유를 선택하면 해당 고객·주문만 볼 수 있습니다. 한 주문에 여러 사유가 겹칠 수 있습니다.
3. **보기**를 누르면 엑셀의 시트·행 위치, 원본 금액, 당시 단가로 다시 계산한 금액, 고객 연결 후보와 체크 상태를 확인합니다.
4. **제품 연결**은 현재 제품과 연결 가능한 후보입니다. 지금 제품 가격이나 용량으로 과거 기록을 고치는 작업이 아닙니다.
5. 다른 파일을 확인할 때만 **엑셀 파일 선택 → 미리보기 만들기**를 사용합니다. 최초 파일로 돌아가려면 **최초 첨부 엑셀 다시 분석**을 누릅니다.

버튼을 눌러 분석해도 고객·주문·입금·제품 테이블은 변경하지 않습니다. 아직 실제 가져오기 버튼은 없습니다.

## 최초 첨부 자료의 분석 결과

- 고객 후보 193명, 주문 후보 948행입니다. 주문 후보에는 제품 수량이 없는 2행이 포함되어 있습니다.
- 원본 그대로는 금액 비교 가능 946행 중 945행 일치, 1행 불일치였습니다. **24 시트 52행**은 사용자 설명에 따라 제품 1개·기타 0개·최종 금액 $25로 정정한 미리보기를 추가했습니다. 검토 기준으로는 946행 모두 일치합니다. 원본 $24와 원본 수량은 보존합니다.
- 최초 확인 대상은 고객 13명, 주문 148행이었습니다. 과거 제품 확인을 반영한 백포기김치 확인까지 반영한 현재 확인 대상은 고객 13명, 주문 85행이며 14개 그룹으로 검토할 수 있습니다. 오류 확정 건수가 아니라 업무 판단 또는 미확인 정보 표시입니다.
- 당시 단가로 계산합니다. 원본 수식의 저장 결과가 없으면 미확인으로 남깁니다. 과거 배달비를 지금 규칙으로 만들어 붙이지 않습니다.

## 다음에 선생님께 확인받을 내용

1. **음수 할인액 59행:** 사용자 설명을 반영하여 -$5인 47행은 과거 배달비 $5 후보로 구분했습니다. 원본 할인액 -$5는 보존하고 해석된 할인액 0·배달비 5를 별도로 표시합니다. 사용자가 확실하지 않다고 하셨으므로 실제 저장 전 확인할 후보로 남깁니다. 다른 음수 금액 12행(-$10 6행, -$70 2행, -$1·-$3·-$18·-$40 각 1행)은 자동으로 확정하지 않습니다.
2. **백포기김치 확인 완료:** 포백5는 백포기김치 5kg입니다. 사용자 요청으로 현재 판매 목록에도 추가했으며 기본가는 최신 엑셀 기준 $50입니다. 과거 각 연도 단가 $45·$50은 유지합니다. 남은 2025년 오이 등은 원래 약자와 과거 금액을 보존하거나 보류하는 기준을 그룹으로 선택할 수 있습니다.
3. **확인한 2024 제품:** N·O열의 ‘열’은 같은 열무김치 3.2kg입니다. 당시 $20·$25 단가를 각각 유지하고 정확한 인상 날짜는 추측하지 않습니다. V열 ‘맛김치’는 맛김치 5kg입니다. P열 ‘오이’는 오이김치이며 무게는 미확인(null)으로 남깁니다. 현재 열무김치 2.5kg 제품 정보를 3.2kg으로 바꾸지 않습니다.
4. **고객 구분:** 같은 이름·닉네임의 고객 4명과 관련 주문, 주소 없는 고객, 제품 수량 없는 행을 별도로 확인합니다. 이름만 보고 합치지 않습니다.
5. **정정한 금액 1행:** 24 시트 52행은 사용자 지시대로 제품 1개·기타 0개·금액 $25를 검토 기준으로 반영했습니다. 원본 파일은 변경하지 않았습니다. 원본 합계, 검토 반영 기준 합계, 재계산 합계를 화면에서 구분합니다.

첫 단계에서는 위 기준을 공통 사유별로 답해 주시면 됩니다. 148행을 모두 직접 수정하실 필요는 없습니다. 제가 확인 답변을 반영하고 남은 예외만 다시 정리합니다.

실제 배송일·입금일·입금 방법은 현재 엑셀의 체크 표시만으로 알 수 없습니다. 미래의 실제 가져오기에서도 날짜나 현금/eTransfer 방법을 임의로 만들어 넣지 않습니다. 실제 고객 원장 저장·중복 합치기·제품 연결 확정은 다음 별도 작업입니다.

정정은 최초 첨부 파일의 SHA-256이 일치할 때만 적용합니다(`config/excel-decisions.json`). 다른 파일의 52행을 잘못 바꾸지 않습니다. 같은 파일을 다시 분석해도 중복 적용하지 않습니다. 수정된 새 파일은 별도 자료로 다시 검토합니다.

과거 제품은 `historical_product.key`로 같은 종류·용량을 연결하고 당시 주문 단가를 별도 보존합니다. 오이김치의 무게를 0이나 현재 제품 무게로 대체하지 않습니다. 판매 금액·개수는 보존하고, 미확인 무게는 향후 kg 통계·재료 계산에서 제외해야 합니다. 현재 판매 목록에 과거 오이김치를 새로 등록하지 않았습니다.


## 그룹으로 한 번에 처리하기

1. **그룹별 처리**를 열고 그룹별 처리 방법을 확인합니다. 각 그룹의 원본 자료도 바로 볼 수 있습니다.
2. 원하는 그룹을 체크하거나 **모든 그룹 선택**을 누릅니다. 금액의 의미가 불명확한 그룹은 기본 처리 방법이 보류입니다.
3. **선택한 그룹에 적용**하면 검토 기준만 저장합니다. 실제 고객·주문을 등록하지 않습니다.
4. 이미 반영한 그룹은 처리 방법에서 **적용 전 검토 상태로 되돌리기**를 고르고 다시 적용할 수 있습니다.

추천 기준은 주소 빈 값 유지, 미확인 무게 보존, 동명이인 별도 유지, 시트보다 실제 주문 날짜 사용입니다. -$5를 배달비로 확정할지는 해당 그룹에서 선택합니다. 다른 음수 금액·고객 연결 불명·제품 없는 행은 확인될 때까지 보류하는 것을 권합니다.

보류 자료는 사라지지 않습니다. 고객·주문 목록에 보류 표시로 남으며 실제 가져오기에서는 제외합니다. 어떤 고객의 주문인지 불분명한 13행을 한 사람에게 일괄 연결하는 선택은 제공하지 않습니다. 선생님이 채팅으로 그룹 기준을 정해 주셔도 제가 같은 기준을 반영할 수 있으므로 각 행을 직접 수정하실 필요는 없습니다.


## 현재 그룹 처리 상태

사용자 요청에 따라 원본 보존·자동 병합 금지·보류 기준을 13개 그룹에 반영했습니다. 5개 그룹은 기준 반영, 8개 그룹은 가져오기 보류입니다. 초기에는 고객 연결 경고 범위를 넓게 잡아 27행을 보류했습니다. 이후 고유 실명 주문의 경고를 바로잡아 실제 고객 연결 불명은 26 시트 308행 한 건으로 줄었습니다. 사용자 추가 확인 요청에 따라 다른 음수 금액 12행·제품 없는 2행·연도 차이 2행과 함께 현재 17개 주문 행이 보류되어 있습니다.

사용자가 별도로 지정한 확인 종류 외의 그룹은 일괄 처리해도 된다고 하여 -$5 47행은 과거 배달비로 그룹 확인했습니다. 같은 이름·닉네임 고객 4명은 확인 대기로 되돌렸고, 요청한 주문 종류는 위 17행을 보류합니다. 현재 그룹 상태는 기준 반영 4개·가져오기 보류 9개·고객 확인 대기 1개입니다. 실제 가져오기는 아직 실행하지 않았습니다.

## 최종 사용자 설명 반영

- 25 시트 281·323행은 가져오기 제외로 확정합니다. 삭제하지 않고 원본 위치와 예전 확인 사유를 보존합니다.
- -$1·-$3·-$10·-$18은 고객 동의를 받아 추가로 받은 금액입니다. 9건 합계 $82를 김치 매출·배달비·다음 주문 잔액과 구분한 추가 수입으로 보존합니다. 고객 잔액은 0이며 최종 입금 총액에 다시 더하지 않습니다.
- -$40·-$70은 김밥 판매 대금입니다. 3건 합계 $180을 기타 판매로 구분합니다. 김밥 수량과 단가는 알 수 없으므로 null로 보존합니다.
- 기존 -$5 47행의 배달비 그룹 확인은 유지합니다.
- 25 시트 346·347행은 주문일 2026-01-01 그대로, 집계 연도 2026년으로 분류합니다. 원본 시트 위치는 유지합니다.
- 고객명단 11·27·159행은 개인 고객이며 소속을 별도 기록하고 닉네임을 ‘소속 + 실제 성명’으로 구분합니다. 35행은 단체 고객이며 원본 아이디는 담당자로 분리합니다. 단체의 원장과 개인의 원장을 합치지 않습니다.
- 26 시트 308행은 사용자 확인에 따라 고객명단 35행의 단체에 연결합니다.

이 변경은 최초 원본 파일에만 적용되는 미리보기 규칙입니다. 개인 식별 이름은 원본 비공개 자료에서 읽고 규칙 파일에 하드코딩하지 않습니다. 현재 총 948행 중 제외 2행, 보존 대상 946행이며 검토 대기·보류는 0입니다. 그룹으로 확인한 무게 미확인 등의 원본 정보는 계속 보존합니다. 실제 고객·주문 가져오기는 아직 실행하지 않았습니다.

현재 고객 관리 DB에는 개인/단체·담당자 필드가 아직 없습니다. 이번 분류는 미리보기에 반영한 데이터 설계이며, 실제 가져오기 구현 시 정식 고객 필드와 기타 판매·추가 수입 구조를 함께 추가해야 합니다. 기존의 김치 주문·입금 표에 억지로 합쳐 저장하지 않습니다.
