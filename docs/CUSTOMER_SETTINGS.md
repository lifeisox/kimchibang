# 고객·통계·브랜드 화면

고객 이름만 필수입니다. 고객 종류는 기본 개인, 기본 수령 방법은 집으로 배달이며 두 목록에는 ‘선택 안 함’이 없습니다. 기존 미지정 고객도 수정 화면에서는 이 기본값으로 시작하며 저장할 때 반영합니다. 지역 목록·고객 메모·소속·담당자·입금자 성명은 유지합니다.

고객 원장의 ‘새 주문 넣기’ 버튼과 그 화면에서의 사이드바 ‘새 주문 넣기’는 해당 고객을 선택한 상태로 엽니다. 고객 메모와 수령 방법을 복사하되 주문마다 수정할 수 있고, 고객 변경이 기존 주문을 바꾸지 않습니다.

통계 필터는 데스크톱에서 한 행으로 정렬하고 작은 화면에서는 간격을 유지해 줄바꿈합니다. 매출 표시는 판매금액 / 배송비 / 기타수입 3개입니다. 기타수입은 기존 기타 판매·기타 청구·동의받은 추가 수입을 중복 없이 합산합니다. 원래 저장 구분을 무조건 덮어쓰지 않습니다.

생산·재료 계산은 사용자 요청으로 제거했습니다. 메뉴와 화면·계산 코드는 제거하고 기존 주문·원본 생산 체크는 삭제하지 않습니다.

## 로고 원본 적용

`/?page=brand`에서 가로형 원본 PNG를 직접 선택해 미리 확인한 뒤 적용합니다. 현재 채팅 도구가 인라인 이미지를 원본 파일로 제공하지 않으므로 앱 업로드를 사용합니다. 색·글자·투명 배경을 바꾸지 않고 원본 바이트를 그대로 보존합니다. CSS에서 원래 비율을 유지해 축소하며 이미지 캐시를 재검증해 전송량을 줄입니다. 사각 ‘로’ 임시 로고는 표시하지 않고 원본 적용 전에는 텍스트만 보여줍니다.

PNG 2MB·가로세로 6000px 이하만 받습니다. 로그인·CSRF 검사 후 공개 실행 경로 밖 `.local/branding/logo.png`에 저장합니다. 이미지 전용 응답으로만 제공하므로 PHP로 실행되지 않습니다. 업데이트 후에도 유지되지만 Hostinger 이전 시에는 DB 외에 이 로고 파일도 함께 옮겨야 합니다.

## Codespaces 업데이트

```sh
cd /app
(command -v git >/dev/null || (apt-get update && apt-get install -y git)) && git -c safe.directory=/app pull --ff-only origin codex/cloud-preview && php scripts/apply-cloud-update.php
```

완료 후 Ctrl+F5로 새로고침합니다. 기존 고객·주문을 백업하고 건수를 확인하며 충돌 시 강제로 덮어쓰지 않습니다. 가져오기를 아직 하지 않았다면 새 ‘엑셀 가져오기’ 메뉴에서 파일을 선택해 실행합니다. 로고 화면은 앱 주소 뒤에 `/?page=brand`를 붙여 엽니다.

## 선입금과 전달은 독립 처리

주문 등록 직후부터 전체 주문의 남은 대금 이내에서 선입금을 기록할 수 있습니다. 입금 완료가 전달 완료를 뜻하지 않으며 나중에 배송·픽업·교회 전달을 별도로 기록합니다. 부분 입금·분할 전달도 가능합니다. 입금은 먼저 전달한 제품의 미입금과 발생한 배송비에 배정하고, 나머지는 주문 행 순서로 대기 제품에 선입금 배정합니다. 이 배정은 전달 사실이나 실제 생산 여부를 뜻하지 않습니다.

이미 전달했거나 입금이 배정된 수량은 수정 시 줄일 수 없습니다. 입금되지 않은 대기 수량은 취소할 수 있고 입금 기록은 보존합니다. 완납 주문의 수정·취소는 잠그되 나중의 전달 처리는 허용합니다. 입금 취소·환불은 아직 별도 정정 기능이 없어 임의 삭제하지 않습니다.
