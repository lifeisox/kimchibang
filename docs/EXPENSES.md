# 비용·영수증 / 영수증 읽기

2026-11-15 요청으로 추가한 클라우드 검토용 기능입니다. Hostinger에는 이 코드를 별도로 배포해야 합니다. 사용자 확인: GST/HST 등록 사업자, 사진·Amazon PDF·중국 구매 수동 입력을 함께 사용합니다. 기존 고객·주문·입금과 분리되어 있습니다.

## 메뉴와 사용 흐름

홈 화면의 **비용·영수증** 메뉴는 기본 접힘입니다. 비용 목록 / 사진·비용 입력 / 신고용 집계로 구분합니다. 비용 화면의 **비용 엑셀 가져오기**로 원본 장부를 미리 확인할 수 있습니다.

1. 사진 촬영 또는 사진/PDF 선택 → **선택한 영수증 자동 읽기**.
2. 날짜·구입처·공급가·GST/HST·기타 세금·총액을 확인합니다. 영문 OCR만 기본 제공하고, 글자가 들어 있는 PDF를 읽습니다. 스캔 PDF·HEIC는 JPG 사진 또는 직접 입력을 사용합니다.
3. 비용 항목·사업 사용 비율·소득세 비용 인정 비율·GST/HST 검토 상태를 입력하고 저장합니다. 해외 구매는 실제 카드 CAD 청구액을 입력하고 외화 원금은 메모에 기록합니다. 외국 세금을 캐나다 GST/HST에 넣지 않습니다.
4. 기존 비용을 열어 증빙을 추가하거나 내용을 수정할 수 있습니다. 취소는 사유와 이력을 남기며 집계에서 제외하고 영수증을 지우지 않습니다.

자동 읽기는 초안이며 저장하지 않습니다. 이미지·PDF는 기기 안에서만 읽고 외부 OCR·AI·유료 API로 보내지 않습니다. 영어 모델과 PDF/OCR 프로그램도 같은 서버에서 제공합니다. 처음 읽을 때 모델 로딩과 처리가 수 초 이상 걸릴 수 있습니다. 기존 입력 금액을 자동 덮어쓰지 않습니다. 문서에 없는 날짜·통화·세금 적격성·사업 사용 비율을 AI로 추정하지 않습니다.

## 저장과 접근

- 영수증: 비공개 `.local/receipts`, 무작위 파일명, 0600 권한. JPG/PNG/WebP/PDF, 10MB 제한.
- 로그인한 직원만 `/?api=expense-receipt&id=...`로 열 수 있습니다. 원래 파일명·파일 해시·비용 변경 전후와 작업자를 기록합니다.
- `.local`·DB 설정·원본 엑셀·영수증은 GitHub와 배포 ZIP에 넣지 않습니다.
- **DB 백업만으로 사진/PDF가 백업되지는 않습니다.** `.local/receipts`와 `.local/expense-imports`도 별도 안전한 위치에 보관해야 합니다. 코드 업데이트는 이 폴더를 유지합니다.

## 2024·2025·2026 비용 엑셀

원본 파일을 읽되 매크로·수식·외부 연결을 실행하지 않고 저장된 셀 값만 사용합니다. 월별 Date/Amount/HST/Net Amount와 4행 항목 이름을 읽습니다. Cover·Total·Template·Where To Buy 및 월 합계는 비용 거래로 가져오지 않습니다.

- 2024: YYYY-MM 시트.
- 2025/2026: Jan~Dec 시트.
- 17개 원본 항목(Material, Wages, Advertising, Bank, Insurance, Meals, Supplies, Licenses, Professional, Rent, Phone/Internet, Maintenance, Utilities, Auto, Lease, Fixed Assets, Others)을 한국어 항목과 연결합니다.
- 항목별 분할과 원본 셀·시트·행·파일 해시를 보존합니다. 새로 만든 비용과 과거 가져오기를 섞어 고객/주문을 초기화하지 않습니다.
- 파일명 연도와 선택 연도가 다르면 중단합니다. 날짜·행 금액·항목 합계·구입처가 불명확하면 보류합니다. 반올림으로 임의 금액을 맞추지 않습니다.
- 확인된 비용만 백업 후 추가합니다. 연도별 최초 한 번만 가져오며 같은 연도를 반복 가져와 중복 생성하지 않습니다. 기존 수동 비용이 있으면 겹치는지 먼저 확인해야 합니다. 보류 행은 직접 확인·등록합니다.
- 가져온 기록은 사업 사용/공제 적격성을 확정하지 않습니다. GST/HST 상태를 확인 필요로 저장합니다. 초기 100% 비율은 검토용 입력값이며 모든 지출의 사업성을 확정한 뜻이 아닙니다.
- 분할된 엑셀 비용의 금액/분류 수정은 취소 후 재입력합니다. 원본 분할을 단일 항목으로 조용히 덮어쓰지 않습니다. 증빙·메모·검토 비율은 수정 가능합니다.

## 신고 준비 집계

연도별·항목별·월별 지출, 지불한 GST/HST, **증빙 확인된 사업분 매입세액**, 운영비용 검토 금액, 자산을 분리합니다. CSV는 Excel에서 볼 수 있으며 수식으로 오인할 문자열을 이스케이프합니다. 이미지와 원본 PDF는 별도 증빙으로 함께 보관합니다.

GST/HST 매입세액 = 지불한 GST/HST × 사업 사용 비율(공제 대상 확인된 건만). 비용 검토 금액 = (지출 × 사업 사용 비율 − 확인된 매입세액) × 소득세 비용 인정 비율. 항목별 분할은 센트 합계를 보존해 배분합니다. 자산은 일반 운영비에서 제외하며 CCA 감가상각을 계산하지 않습니다.

이 화면은 신고 준비용 집계입니다. 사업 사용/비용 인정 비율·Meals·차량·가정 공용비용·증빙을 검토하고 실제 세무 신고 기준에 맞춥니다. 김치방 외 마트/케이터링 매출은 포함하지 않습니다. 매출 GST/HST 및 기신고액/납부액을 관리하지 않으므로 최종 납부·환급액을 확정하지 않습니다. 현재 출력은 달력연도(1~12월) 기준이며 월별 매입세액을 제공합니다.

## 부가 변경

메뉴는 간격을 줄이고 자체 SVG 아이콘을 사용하므로 별도 Font Awesome 요금·CDN이 없습니다. 주문 목록은 미전달·미입금 → 전달·미입금 → 선입금·미전달 → 완료 순서, 각 그룹 최근 거래 순입니다. 미전달 이름/상태는 적색, 미입금 상태는 청색입니다.

재료 구입량 계산은 생산 화면 버튼에서 열며 현재 배합의 1kg당 필요량으로 kg 입력 즉시 계산합니다. 저장·생산 확정·배달 상태 변경이 없습니다. 새 재료나 배합은 기존 기준 관리에서 추가합니다.

최근 3년 비교는 선택 날짜의 연도와 이전 2개 달력연도입니다. 주간 52행/월간12행/연간1행 + 맨 위 합계입니다. 정확히 52행으로 모든 날짜를 합산하기 위해 1월1일부터 7일 간격, 52주에 남은 연말 날짜를 포함합니다. ISO 주차가 아니며 화면에 이 정의를 표시합니다. 각 증감률은 오른쪽 전년도 금액 기준이고 기준액0은 —입니다. 자료 미입력 기간0을 확인된 무매출로 단정하지 않습니다.

검증: `python tests/finance.py`, `python tests/production.py`, `python tests/sales.py`, `python tests/hostinger-package.py`, `python tests/hostinger-update.py`. 영수증/원본 파일은 별도 시험 DB에서만 가져와 테스트합니다.
