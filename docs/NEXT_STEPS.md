# 다음 진행 안내

## 현재 완료한 기능

고객·제품 관리, 주문 입력·검색·원장, 주문 수정·취소 이력, 부분 배송, 분할 입금, 완납 주문 잠금과 엑셀 가져오기 미리보기·그룹별 기준 일괄 적용·백업 후 실제 가져오기가 있습니다. 배달비는 **할인 전 제품 합계 $80 미만이면 $5**, 픽업은 무료입니다. 새싹 모양을 참고한 파비콘은 적용했습니다. 브랜드 원본 그대로의 적용은 별도 미완료 항목이며 기존 구성을 만든 PNG와 구분합니다.

## 지금 선생님이 하실 일

개발용 DB에 최초 확인한 고객 193명과 주문 946건을 가져왔습니다. 제외 2건과 원본 위치는 이력에 보존했습니다. 실제 운영 서버로 배포하거나 환경을 게시하지 않았습니다.

1. **고객 찾기**에서 고객 원장과 과거 주문을 확인합니다.
2. 고객과 입금자가 다르면 **고객 정보 수정 → 주로 입금하는 분 성명**에 은행에서 보이는 이름을 적습니다. 비고·닉네임의 기존 내용은 자동으로 옮기지 않았습니다.
3. 새 주문 대금을 받을 때 **입금 기록하기 → 이번 입금자 성명**을 기록합니다. 빈칸은 미기록으로 남고 고객 기본 정보 변경이 과거 입금자 기록을 바꾸지 않습니다.

입금자 이름으로도 고객을 검색할 수 있습니다. 입력이나 검색이 불편한 부분만 알려주시면 됩니다. 코딩이나 DB 명령을 직접 입력하실 필요는 없습니다.

사용자 결정에 따라 최신 엑셀 비교 기능은 개발하지 않습니다. 소량의 추가 고객·거래는 앱의 고객 등록과 새 주문으로 입력합니다. 변경된 엑셀 전체를 다시 가져오지 마세요. 동일 파일 재실행의 중복 방지만 지원합니다.

## 남은 업무 결정

- 주문·입금 실수를 바로잡는 정정이나 환불·반품은 아직 없습니다. 잠근 기록을 임의로 삭제하지 않고 별도 정정 이력을 남기는 기능으로 추후 다룹니다.
- 재료 계산을 시작하기 전 엑셀의 빈 배합값, 소금 메모와 수식의 차이, 동치미 용량을 확인해야 합니다. 제품 판매 용량은 사용자가 확정한 3.2kg을 사용합니다.
- 엑셀 이전 때 이름이 같은 고객과 모호한 과거 제품을 확인 목록으로 분리하고 금액을 대조합니다. 최초 확인한 엑셀 자료는 개발용 DB에 가져왔습니다.

## 진행 순서

가상 주문 업무 시험 → 엑셀 가져오기 미리보기·대조 → 생산·재료 계산 → 통계 → Hostinger 시험 배포 → 운영 전환을 권합니다. 카카오 직접 주문은 이후 확장합니다. 기술 설계와 코드는 제가 맡고 선생님은 실제 업무 기준과 화면 사용성을 확인하면 됩니다.

지금은 Hostinger·도메인 설정을 바꾸지 않아도 됩니다. 이번 작업은 개발 환경에서만 진행하며 환경 게시와 운영 서버 배포는 하지 않습니다. DB 비밀번호를 채팅에 보내지 마세요. 사용법과 백업·복구 방법은 README.md에 있습니다.

## 사용량 관리

정확한 요금제·남은 한도·모델별 차감 방식은 계정 사용량 화면에서 확인해야 합니다. 제가 한 달 사용량으로 전체 개발이 끝난다고 보장할 수는 없습니다. 승인한 화면은 유지하고, 변경 사항을 모아 요청하고, 금액·DB·배포 검토에 높은 추론을 집중하면 재작업을 줄일 수 있습니다.

사용자 후속 설명을 반영하여 확인 대기·보류는 0입니다. 실제 가져오기 기능과 원본 전체 시험, 백업 복원 시험을 완료했습니다. 실제 개발용 DB로 최초 자료 가져오기를 완료했습니다. 최신 파일 증분 가져오기는 사용자 요청으로 취소했습니다.


## 직접 테스트와 통계

사용자 선호에 따라 Windows 로컬 설치는 진행하지 않습니다. [클라우드 미리보기 안내](CLOUD_PREVIEW.md)의 GitHub Codespaces를 사용해 브라우저 링크로 확인하고 완성 후 Hostinger에 배포합니다. Codespaces 최초 생성은 사용자 계정에서 한 번 시작해야 하며 비용·무료 사용량은 GitHub 표시를 확인합니다.

판매 통계에 주간·월간·연간 선택, 전년도 비교, 용량별 제품 판매량, 별도 수입 구분과 입금일 기준 집계를 추가했습니다. 입금일 미기록 자료는 주문일을 입금일로 추정하지 않습니다. 현재 진행 중인 기간과 전년도 전체 기간을 비교할 때의 차이를 화면에 안내합니다. 다음 개발은 생산 계획·재료 계산이며 배합 기준 확인이 필요합니다.


## 진행 방식에 대한 최신 결정

클라우드에서 개발·미리보기 테스트 후 완성된 앱을 Hostinger로 옮깁니다. Windows 로컬 설치는 요구하지 않습니다. 코드 저장·별도 개발 브랜치·기본 테스트·미리보기 설정은 개발자가 진행합니다. 새 계정 연결, 유료 사용이나 실제 운영 전환처럼 사용자 결정이 필요한 부분만 구체적으로 안내합니다. GitHub Codespaces는 사용자 GitHub 계정에서 최초 생성이 필요하며 생성 전 비용·포함 사용량을 확인합니다.
