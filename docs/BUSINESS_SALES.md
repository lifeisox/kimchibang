# Rodem Namu 판매 관리 개발판

판매 관리 → 김치방 → 기장 메뉴 순서이며 개발 환경에서만 켭니다. 현재 Hostinger 판매·기장 배포판에는 새 판매 관리 코드와 제품 자료를 포함하지 않습니다. 기존 판매/기장 거래를 변경하거나 Geeland 기록을 지우지 않습니다. 새 판매 관리에는 Geeland와 Cheese 제품을 등록하지 않습니다.

## 시작

`codex/business-sales` 브랜치를 갱신한 기존 Codespace에서 다음을 실행합니다.

```sh
php scripts/enable-business-preview.php
sh scripts/cloud-start.sh
```

미리보기 표시는 현재 DB에만 적용되며 운영 배포판에서는 켜지지 않습니다. 기존 DB와 계정을 보존하고 별도 `biz_` 테이블을 추가합니다.

1. 거래처 관리에서 사업자 주소/GST 번호와 세 거래처의 주소/이메일, 개인 고객을 입력합니다.
2. 판매상품 관리에서 한글·인보이스 제품명과 정가를 입력하고, 별도 납품가 관리에서 거래처별 가격을 입력합니다. 정가는 빈 값으로 시작합니다. 김치방/생산 전용 기존 제품과 별도 관리합니다.
3. 주문서 관리 → 주문서 입력에서 거래처·납품 예정일·할인율·비고와 분류별 수량을 입력합니다. Enter/위아래 방향키로 다음 수량 칸으로 이동하며 분류별/전체 합계가 바로 바뀝니다. 받는 방법은 입력하지 않습니다.
4. 생산량에서 날짜별 전체 제품 수량과 확인된 재료 소요량을 보고 인쇄합니다.
5. 자동 생성된 납품서에서 실제 수량을 확인합니다. 주문서를 수정·삭제하면 납품서도 함께 반영됩니다. 납품서를 직접 수정하면 원 주문서의 수정·삭제가 잠깁니다. 납품서 자체 삭제는 제공하지 않습니다. 납품 완료 후 수량을 보존합니다. 직매출은 같은 계획의 직매출 제품 납품이 모두 끝나면 하나의 인보이스가 발행됩니다. 위탁품은 매출로 잡지 않습니다.
6. 실판매·반품에서 판매 수량과 반품/폐기를 추가 입력합니다. 직원 차감은 인보이스에서만 입력합니다. 남은 재고를 넘을 수 없습니다. 0개 판매일도 마감합니다. 재고가 남으면 다음 날에도 같은 납품 건에 추가 판매를 기록합니다.
7. 정산·인보이스에서 기간을 선택해 위탁판매분을 발행합니다. 인보이스는 한영 제품명, 당시 단가/할인/세금/발신 정보의 스냅샷을 보존합니다.
8. 현금/eTransfer 수금은 인보이스별로 기록하며 분할 수금과 잔액을 관리합니다.

## 거래처 규칙

- OK Mart: 김치는 납품가로 즉시 직매출. 김밥·삼각김밥·주먹밥은 정가 기준 위탁. 실제 판매의 품목별 합산 금액에 20% 할인 후 HST 13%. 전주 월~일 정산.
- Popularitea: 김치는 납품 즉시 판매로 기록하되 청구는 삼각김밥 실판매와 함께 월 단위로 합니다. 나머지 위탁품은 실판매만 기록합니다. 전 품목 거래처 납품가. 직원 판매 차감은 월 정산 화면의 Staff Purchases에 수량과 개당 차감액(엑셀 38행 기준 $1.50)을 넣습니다. 실제 판매 수량·재고는 변경하지 않고 인보이스에 별도 음수 행을 추가한 뒤 HST를 계산합니다. 월초 5일경 직원 판매 수량을 통보받은 뒤 전월 기간과 직원 확인란을 선택해 한 번 발행합니다. 직원 수량은 일반 판매 기록과 별도로 인보이스에만 입력하며, 이 단계에서 판매·재고 수량은 변경하지 않습니다.
- Hungry Ninja: 납품 수량이 판매 수량이며 납품가 적용. 개인과 Hungry Ninja는 인보이스 발행 직후 인쇄 창을 엽니다. 현금 수금은 사용자가 별도로 확인/기록합니다. 자동으로 입금 완료로 만들지 않습니다.
- 개인: 정가와 건별 할인율(현금은 보통 10%이지만 자동 적용하지 않음). 수량/픽업에 따른 자동 할인 기준은 아직 정해지지 않아 직접 입력합니다.
- Kimchi는 HST 0%, Kimbap/Triangle Kimbap/Rice Ball은 13%. Etc는 상품 등록 시 HST 0% 또는 13%를 직접 지정하며 미확정이면 납품을 막습니다. 납품한 상품의 분류·세율은 잠그고 인보이스에 분류/세율을 보존합니다. 모든 금액은 정수 센트로 저장합니다. 합산 할인/세금을 반올림하고 센트 잔차를 배분합니다.

정산한 기간의 추가 위탁판매, 과다 판매/반품, 초과 수금, 동일 기간 재발행, 중복 제출을 차단합니다. 발행 후 반품/취소/환불/수금 정정용 Credit Note는 다음 단계이며 현재 잠긴 기록을 직접 수정하지 않습니다. 납품서 수정 전 주문서는 수정·삭제할 수 있으며 삭제 시 연결된 납품서도 취소합니다. 동시 수정과 취소 후 납품을 차단합니다. 현재 버전은 개발 시험용입니다.

## 생산 기준

엑셀 ‘생산량’ 시트의 확인 가능한 김밥·기본 삼각김밥 재료 공식을 옮겼습니다. 쌀/계란은 부족하지 않게 올림합니다. 주먹밥과 추가 맛의 전용 배합은 확인되지 않아 ‘배합 확인 필요’로 표시합니다. 삼각김밥 배합을 주먹밥에 임의로 적용하지 않습니다. 김치는 기존에 등록된 주재료 배합을 읽어 새 판매 규격의 무게로 계산하며, 기존 김치방 생산계획의 배합/마트 제품은 변경하지 않습니다. 재료 준비표는 완성된 전 제품 배합표가 아닙니다.

## 이메일과 자동 정산

`scripts/business-cron.php`의 기본 실행은 점검만 합니다. `--run`은 월요일 오타와 시간 08:00 이후 전주 정산을 확인하며, 해당 기간 재고가 있었던 모든 납품 건의 일일 마감이 없으면 발행을 보류합니다. 인보이스는 먼저 수량·금액을 확인하고 발행하세요.

`--run --send`와 운영 설정 `BIZ_MAIL_ENABLED=1`이 함께 있어야 PHP mail()을 호출합니다. 현재는 꺼져 있으며 실제 이메일을 보내지 않았습니다. Hostinger cron 실행 시각, 도메인 발신 이메일·SPF/DKIM·수신 테스트를 마쳐야 자동 발송을 활성화합니다. 발신 설정에는 비밀번호를 채팅에 보내지 않습니다. cron은 오타와 시간으로 판단하므로 호스팅의 UTC/DST 설정과 일치하는지 확인합니다.

OK/PT 인보이스는 발행 시 발송 대기, 다른 거래처는 수동 상태로 시작합니다. 메일은 인보이스를 HTML 본문에 넣으며 PDF 첨부는 아직 아닙니다. 인쇄 화면에서 PDF 저장은 가능합니다. 메일 서버 접수(accepted)와 실제 도착은 구분합니다. 실패·중단된 발송은 도착 여부를 확인한 후 인보이스 화면에서 다시 대기 등록합니다. 중복 메일을 피하기 위해 sending 상태는 자동 재발송하지 않습니다.

## 첨부 엑셀 분석 범위

OK DAT, PT DAT, NJ DAT, 각 계획/결과, 생산량, 배합표, CUSTOMERS, 인보이스 양식을 확인했습니다. 파일에 2024/2025 기록과 현재 제품 목록에 없는 과거 규격, Cheese, 50% 할인용 열이 섞여 있습니다. 과거 거래는 아직 DB에 가져오지 않았습니다. 이전 단가를 현재 단가로 임의 등록하지 않습니다. 과거 데이터 가져오기는 규격·판매/납품·기간을 검토한 별도 단계로 진행합니다. 원본 엑셀은 비공개로 보관하며 Git에 넣지 않습니다.

## 검증

`python tests/business.py`는 임시 DB와 HTTP/브라우저에서 메뉴 순서, 제품 31종, 위탁/직매출, 재고 제한, 정산, 직원 할인, HST, 이중 발행, 수금, 모바일/PC, 최대 품목 인보이스 A4 한 페이지를 확인합니다. 실제 이메일은 보내지 않습니다.

최초 요청 재점검은 [2026-11-21 점검표](SALES_REVIEW_20261121.md)를 참고하세요. 운영 전 미완료 범위를 구분했습니다.

## 2026-11-21 주문서·납품서 화면 개편

- 모든 업무 화면의 제목 오른쪽 날짜와 판매 관리의 중복 상단 메뉴를 제거했습니다. 영수증 입력에는 기장 내역으로 돌아가는 링크가 있습니다.
- 거래처와 판매상품은 줄 단위 수정, 별도 카드 추가를 지원합니다. 거래내역이 한 건이라도 있으면 삭제 버튼을 숨기며 서버에서도 거부합니다. 삭제는 비활성화로 기록하여 초기화 시 재생성되지 않습니다.
- 판매상품 분류는 Kimchi / Kimbap / Triangle Kimbap / Rice Ball / Etc입니다. 기존 용량은 보존하며 새 상품은 제품명에 용량을 함께 적을 수 있습니다. 분류별 수량 합계와 인보이스의 분류 스냅샷으로 후속 통계에 연결합니다.
- 납품가 관리에서 거래처를 선택하여 등록/수정/삭제하고 정가를 복사할 수 있습니다. 기존 인보이스의 가격은 변하지 않습니다.
- 주문서 목록은 작성일(기본 오늘), 납품서 목록은 예정일(기본 전체) 기준입니다. 기존 납품 묶음도 연결하되 과거 작성일이 없던 자료는 납품 예정일을 작성일로 사용합니다.
- 미리보기 인쇄는 PRO FORMA INVOICE로 표시하고 청구 매출/수금 잔액에 반영하지 않습니다. 실제 인보이스는 기존 직매출/위탁 정산 시점에 발행하며 납품서에서 발행본으로 이동할 수 있습니다.
- 새 주문서는 화면에 입력한 수량을 저장하고 전체 납품을 한 트랜잭션으로 확정합니다. 품목 하나의 가격·세율이 누락되어도 일부만 매출로 남지 않습니다.

검증: 새 주문서·납품서 생성/동기화/동시 수정/삭제 제한/확정 실패 롤백, 거래처·상품 삭제 제한, 단가 복사, 키보드 입력, 390px/1440px 가로 넘침 및 A4 인쇄를 시험 DB에서 확인합니다. 기존 김치방·기장 배포판은 새 판매 관리 코드를 포함하지 않습니다.
