# 엑셀 가져오기

최초 자료 이전은 **엑셀 가져오기 → 파일 선택 → 파일 분석하기 → 저장할 내용 확인하기 → 백업 후 실제 가져오기** 순서로 진행합니다. 마지막 실행 버튼 전까지 업무 자료는 변경하지 않습니다.

## 현재 승인한 분류 기준

- 할인액의 -$5는 배송비 $5입니다. 나머지 음수는 모두 기타수입이며 판매금액에 중복 가산하지 않습니다. 이전 김밥·초과 입금 구분보다 이번 지시를 우선합니다.
- 이름에 대사관이 있는 기관은 단체/기관으로, 원본 닉네임의 사람 이름은 담당자로 저장합니다. 나머지 개인은 개인으로 보존하며 대사관 소속이 표시된 닉네임은 ‘대사관 이름’으로 구분합니다. 동명이인을 자동 병합하지 않습니다.
- 현재 판매 목록에 없는 과거 제품은 비활성 **기타** 제품에 연결합니다. 주문 원본의 약자·단가·수량·용량 정보는 원본 스냅샷에 보존하며 당시 단가로 저장합니다. 판매 목록의 가격을 과거 주문에 새로 적용하지 않습니다.
- 제품 수량이 없는 행은 제외합니다. 원본과 제외 사유는 가져오기 이력에 보존합니다. 잘못된 숫자는 없는 수량으로 취급하지 않습니다.
- 시트 연도 차이는 확인 대기에서 제외하며 통계는 실제 주문 날짜를 사용합니다.
- 이전에 확인한 열무김치 3.2kg, 맛김치 5kg, 백포기김치 5kg 기준은 유지합니다. 오이김치 등 알 수 없는 용량은 추정하지 않습니다.
- 최초 첨부 원본에만 적용하는 24!52의 수량·금액 $25 정정은 원본 보존과 함께 유지합니다. 다른 파일의 같은 행에 정정을 무조건 복사하지 않습니다.

최초 첨부 원본을 시험 DB에 가져온 결과는 고객 193명·주문 946건·제외 2행, 판매금액 $77,350 + 배송비 $235 + 기타수입 $262 = $77,847입니다. 입금 완료 표시는 $77,747, 미입금은 2건 $100입니다. 날짜 없는 과거 입금에 주문 날짜를 대신 넣지 않습니다.

## 개발용 메뉴와 최종 운영 메뉴

Codespaces 개발·테스트에서는 가져오기 후에도 메뉴를 유지합니다. 동일 원본의 같은 행은 건너뛰며 이미 가져온 내용이 바뀌면 덮어쓰지 않고 중단합니다. 새 파일과의 증분 비교 기능은 구현하지 않습니다. 다른 파일에 대한 무조건 재가져오기는 중복 위험 때문에 하지 않습니다.

Hostinger 최종 배포에서는 서버 환경 변수 `APP_HIDE_IMPORT_AFTER_COMPLETE=1`을 설정합니다. 이 설정이 켜져 있고 보류 없이 주문을 실제 가져온 이력이 있을 때 메뉴를 숨기고 추가 가져오기 요청도 차단합니다. 개발 환경에서는 이 옵션을 켜지 않습니다.

이미 이전 규칙으로 가져온 DB는 이번 코드 업데이트만으로 재분류하거나 덮어쓰지 않습니다. 원본과 가져오기 이력을 유지합니다. 실제 자료 정정은 백업·금액 대조 후 별도 작업입니다.

## 보존·백업

실행 전 전체 DB 백업은 웹 루트 밖 `.local/import-backups/`에 권한 0600으로 저장하며 실행 기록에 파일명과 SHA-256을 남깁니다. 오류는 한 트랜잭션으로 롤백하고 백업은 보존합니다. 고객·주문 쓰기와 가져오기는 DB별 잠금으로 직렬화합니다. 과거 주문은 원본 추적이 가능한 조회 전용이며 현재 주문의 배송·입금 기능과 구분합니다.

복원 도구는 `scripts/restore-import.php`입니다. 사용자 명시적 복원 요청 후 현재 DB와 일치하는 백업으로 수행하며, 복원 직전에도 안전 백업을 만듭니다. SQL 복원은 유지보수 중 진행합니다. 고객 자료·백업·비밀번호는 Git에 넣지 않습니다.
