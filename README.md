# 로뎀나무 김치방 판매관리

오타와 Rodem Namu의 직원용 판매관리 첫 버전입니다. PHP 8.5, MySQL 8.4, HTML/CSS/JavaScript로 구성했습니다. 외부 CDN이나 별도의 PHP 패키지는 사용하지 않습니다. 날짜는 `America/Toronto`, 금액은 CAD이며 DB에는 정수 센트로 저장합니다.

## 권장: 클라우드에서 개발·테스트

[클라우드 링크 테스트 안내](docs/CLOUD_PREVIEW.md)를 참고하세요. GitHub Codespaces에서 PHP·MySQL을 실행하고 비공개 HTTPS 링크로 확인합니다. 로컬 설치는 필요 없습니다. 최초 Codespace 생성과 사용량 확인은 사용자 GitHub 계정에서 진행하며, 준비 후 앱에서 관리자 비밀번호를 직접 정합니다. 실제 Codespace 링크는 생성 후 확인합니다. 완성 후 Hostinger에 배포합니다.

## 시작하기 — 내부 개발 환경

Docker Compose와 Python 3가 설치된 작업 환경에서 실행합니다.

```sh
cd /workspace/kimchibang
./scripts/dev.sh
```

이 명령은 개발용 비밀번호 생성 → PHP/MySQL 실행 → 테이블 및 14개 제품 초기 등록 → 최초 관리자 계정 생성을 수행합니다. 재실행해도 기존 주문, 변경한 제품 가격, 비밀번호를 덮어쓰지 않습니다. 기존 체크아웃을 그대로 사용하며 별도의 Git worktree는 만들 필요가 없습니다.

내부 개발 주소는 `http://127.0.0.1:8080`입니다. 이것은 선생님 컴퓨터의 localhost 주소가 아니라 실행 중인 작업 환경 내부 주소입니다. 실제 공개 서비스 주소는 아직 없습니다. 클라우드의 웹 접근 기능이 제공되는 경우 포트 8080으로 연결해야 합니다.

- 아이디: `admin`
- 최초 개발 비밀번호: `.local/admin-password.txt` 파일에서 확인합니다. 비밀번호를 Git이나 채팅에 올리지 마세요.
- 두 번째 계정: 12자 이상의 비밀번호를 안전한 임시 파일에 적은 뒤 아래 명령을 실행하고 임시 파일을 삭제합니다.

```sh
docker compose exec -T web php scripts/create-user.php second-user < /안전한/임시파일
```

개발 환경은 HTTP이므로 Compose에서 `APP_SECURE_COOKIE=0`을 사용합니다. 운영은 반드시 HTTPS와 `APP_SECURE_COOKIE=1`을 사용합니다.

## 사용하는 순서

1. 로그인 후 **고객 찾기 → 고객 등록**에서 이름, 닉네임, 주소를 입력합니다. 전화번호·메모는 선택 사항입니다.
2. **새 주문 넣기**에서 고객을 검색하고 결과를 선택합니다. 제품의 `＋` 버튼으로 수량을 정합니다.
3. 주문일, 배달·픽업일, 받는 방법, 주소, 필요하면 할인액과 메모를 적습니다.
4. 배달 주문은 **할인 전 제품 금액 $80 미만이면 배달비 $5**, $80 이상 또는 직접 픽업은 무료입니다. 배달비는 주문에 별도 저장하고 기존 주문에는 소급 부과하지 않습니다. 오른쪽 금액을 확인한 뒤 **주문 저장하기**를 누릅니다.
5. 주문 상세에서 이번에 전달한 제품 수량을 입력하고 **선택 수량 전달 완료**를 누릅니다. 전달한 제품의 미입금액 이내에서 eTransfer 또는 현금 입금을 여러 번 기록할 수 있습니다.
6. 미생산 제품은 **주문 수정·대기 제품 취소**에서 대기 수량을 0으로 바꾸어 취소하거나, 수량을 남겨 두고 다음 전달 예정일을 정합니다. 전체 미배송·미입금 주문은 사유를 남겨 전체 취소할 수 있습니다.
7. 이미 전달한 수량과 입금 이력은 보존합니다. 완납한 주문은 수정·취소가 차단됩니다. 과거 입금·배송 기록을 지우거나 되돌리는 기능은 제공하지 않습니다.
8. **고객 원장**에서 누적 주문 금액과 미입금, 최근 주문을 확인합니다.
9. **제품과 가격**에서 제품 추가·수정·판매 중단을 처리합니다. 기존 주문의 제품명·용량·단가·주소는 변경되지 않습니다.

제품 선택 및 제품 관리 화면은 포10 → 포5 → 맛10 → 맛5 → 깍 → 파 → 겉 → 물 → 물백 → 동 → 총각 → 갓 → 열 → 포백5 순서입니다. 나중에 추가한 제품은 뒤에 표시합니다.

이번 주 화면은 월요일~일요일 **배달·픽업 예정일** 기준입니다. 전체 미입금은 기간 전체 기준입니다. 고객명 중복은 허용하므로 주소·전화번호를 함께 확인해 주세요.

## 데이터와 백업

- DB 파일은 `.local/mysql/`에 저장하며 Git에서 제외합니다. 컨테이너를 재생성해도 이 폴더를 보존하면 자료가 유지됩니다.
- `.env`에는 자동 생성한 개발용 DB 비밀번호가 있습니다. 이 파일과 `.local/`을 삭제하지 마세요.
- 클라우드 작업 공간이나 Docker의 보존 정책만을 백업으로 간주하지 마세요. 주기적으로 SQL 백업을 별도 안전한 위치에도 보관해야 합니다.
- 백업: `./scripts/backup.sh` → `backups/`에 SQL 생성. 해당 폴더도 Git에서 제외합니다.
- 복구는 기존 자료를 덮어쓸 수 있습니다. 먼저 현재 자료를 백업하고, 새로운 빈 개발 DB에 복구를 시험하세요.

```sh
# 새 DB 또는 복구 대상 확인 후 실행할 예시 (실행 시 데이터가 바뀜)
docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysql -u "$MYSQL_USER" "$MYSQL_DATABASE"' < backups/선택한백업.sql
```

중지: `docker compose stop` / 다시 시작: `./scripts/dev.sh`.

python3 tests/smoke.py

Playwright가 없으면 `npm install --prefix .local/browser playwright`로 개발용 도구만 설치한 뒤 `NODE_PATH="$PWD/.local/browser/node_modules" node tests/browser.cjs`로 실행하세요. 가상 고객과 주문은 검증 종료 시 정리하며, 화면은 `.local/screenshots/`에 저장합니다.

## Hostinger로 옮길 때

아직 운영 서버에는 설치하지 않았습니다. 배포 시 다음을 확인해야 합니다.

- 실제 PHP 버전과 `pdo_mysql` 확장, MySQL 버전, HTTPS 및 DB 접근 권한 확인
- 도메인의 document root를 **public/**으로 지정; `.env`, `.git`, app/, scripts/, database/, backups/는 웹에 공개하지 않기
- DB 접속 변수 `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`를 호스팅의 안전한 서버 설정으로 제공; PHP 부트스트랩은 `.env`를 직접 읽지 않음
- `APP_SECURE_COOKIE=1`, 오류 화면 출력 끄기, 안전한 서버 오류 로그, 운영 계정 및 백업·복구 검증
- Docker는 개발용입니다. Hostinger에 Docker 설치는 필요 없습니다. DB 스키마와 PHP 파일로 배포합니다.

## 이번 버전의 범위와 다음 단계

로그인, 고객 등록·수정·검색·원장, 14개 제품 및 가격 관리, 주문 입력·목록·상세·인쇄, 대기 수량·예정일 수정, 주문 취소 이력, 부분 전달, 분할 입금·제품별 입금 배분, 완납 잠금을 제공합니다. 중복 제출 방지 키, CSRF 검사, 출력 이스케이프, 매개변수 SQL, 서버 측 금액 계산을 적용했습니다.

환불·반품·입금 기록 정정, 생산·재료 계산, 엑셀 이전, 주월년 통계·예측, 소매점 계획, 카카오 연동, 외부 회계 연동은 아직 구현하지 않았습니다. 주문 변경·전달·입금·취소 이력은 기록합니다. 실제 엑셀의 고객 개인정보를 소스에 포함하거나 DB로 옮기지 않았습니다. 운영 사용 전에는 해당 업무 범위와 배포 보안 검토가 필요합니다.

## 부분 배송과 입금 기준

- **전체 남은 금액**은 대기 제품을 포함한 주문 잔액이며, **이번 전달분 미입금**은 이미 전달한 제품과 최초 배달비에서 받은 돈을 뺀 금액입니다. 수금은 전달분 미입금 이내에서만 가능합니다.
- 입금액은 전달한 제품 순서(주문 행 순서)로 배분하고 남은 금액을 배달비로 배분합니다. 입금 내역은 수정·삭제할 수 없습니다.
- 할인액은 제품별·수량별로 1센트까지 정확히 나누어 저장합니다. 일부 제품 취소 시 해당 제품 몫의 할인도 함께 제외하며 이미 전달한 제품에 배분한 할인은 유지합니다.
- 배송 전 수정은 제품 합계(할인 전) 기준으로 배달비를 다시 계산합니다. 일부라도 배송·입금한 뒤에는 당시 배달비를 유지합니다. 보류 제품을 나중에 전달해도 배달비를 다시 붙이지 않습니다.
- 배송·입금 후에는 대기 수량, 다음 예정일, 주문 메모만 변경할 수 있습니다. 단가·할인 기준·주소·받는 방법·배송 완료 수량은 보존합니다. 다른 제품을 추가하면 추가 시점 가격으로 기록합니다.
- 취소는 삭제가 아닙니다. 전체 취소는 미배송·미입금 주문에서만 가능하며 주문 목록의 **취소한 주문**에서 다시 조회합니다. 부분 배송·입금 주문은 대기 수량만 취소할 수 있습니다.
- 변경은 DB 트랜잭션·주문 행 잠금·화면 버전 확인으로 처리합니다. 입금과 전달의 중복 제출은 동일 요청 키로 막습니다.
- 구형 주문의 전액 입금·전달 여부는 마이그레이션에서 보존합니다. 실제 입금일을 알 수 없는 기록은 날짜 미기록으로 표시합니다.

브랜드 이미지는 승인된 기존 ‘로 + 로뎀나무 + RODEM NAMU’ 구성을 투명 PNG로 준비했습니다. 새싹 파비콘은 첨부 모양을 참고해 이미지 생성 도구로 재구성한 후 작은 크기로 최적화한 파일입니다. 원본 이미지 바이트를 그대로 축소한 파일은 아닙니다.

## 엑셀 가져오기 미리보기

메뉴의 **엑셀 미리보기**에서 최초 첨부 파일의 분석 요약, 확인 사유별 목록, 고객·주문 상세, 제품 연결 후보를 볼 수 있습니다. 새 `.xlsx` 파일도 업로드할 수 있으며 **실제 고객·주문을 저장하는 기능은 이번 단계에 없습니다.**

- PHP의 `Phar`(ZIP 읽기), `zlib`, `SimpleXML`, `libxml`, `mbstring`을 사용합니다. Python·Composer·외부 API는 분석 실행에 필요하지 않습니다. Hostinger에서도 해당 확장 사용 여부를 확인해야 합니다.
- 현재 엑셀의 고객명단 및 연도별 주문 열 구조를 지원합니다. 임의 양식의 엑셀을 자동으로 추측하지 않습니다.
- 엑셀 수식·매크로·외부 연결은 실행하지 않습니다. 저장된 수식 결과와 당시 제품 단가·수량·할인으로 계산한 금액을 대조합니다. 계산 결과가 비어 있으면 0으로 바꾸지 않고 비교 보류로 표시합니다.
- 현재 단가·배달비를 과거 주문에 소급하지 않습니다. 음수 할인, 불명확한 제품 약자, 같은 이름의 고객, 중복 가능 주문은 확인 대상으로 표시합니다. 연결 후보의 용량은 기본적으로 현재 제품 정보입니다. 사용자가 과거 용량을 확인한 제품은 별도의 과거 제품 정보로 표시하며 현재 제품 정보를 바꾸지 않습니다.
- 업로드 원본 임시 파일은 분석 직후 삭제합니다. 결과 JSON은 웹 루트 밖 `.local/imports/`에 보관하고 로그인한 해당 세션에서만 읽습니다. 업로드 결과는 24시간 유효하며 만료 파일은 다음 업로드 때 정리합니다. 최초 첨부 파일·분석 결과는 별도로 보존합니다. 개인정보가 들어 있으므로 Git에 넣지 않습니다.
- `config/php-development.ini`에서 개발 업로드 8MB·POST 10MB를 설정합니다. 운영 호스팅에서도 동일하거나 더 큰 업로드 제한을 확인해야 합니다. 파일 내부 크기·셀 수·행 수·XML 외부 정의 검사도 적용합니다.
- 결과는 분석 당시의 시스템 자료와 비교한 스냅샷입니다. 최초 첨부 파일은 **최초 첨부 엑셀 다시 분석**으로 현재 DB와 다시 비교할 수 있습니다.

최초 첨부 파일이 `.local/imports/attached-source.zip`에 준비된 환경에서는 다음 명령으로 비공개 기본 결과를 다시 생성할 수 있습니다. 다른 사용자 원본 파일을 Git에 복사하지 마세요.

```sh
docker compose exec -T web php scripts/prepare-preview.php
python3 tests/excel-preview.py
NODE_PATH="$PWD/.local/browser/node_modules" node tests/browser-preview.cjs
```

분석 결과 해석과 다음 업무 확인 사항은 [엑셀 미리보기 안내](docs/EXCEL_PREVIEW.md)를 참고하세요.

검토 중 확인한 정정·해석은 `config/excel-decisions.json`과 `app/excel-decisions.php`에서 원본 파일 단위로 적용합니다. 원본 엑셀과 고객·주문 DB를 수정하는 기능이 아닙니다. 원본 금액·원본 수량과 검토 반영 기준을 함께 보존하며, -$5 배달비 분류도 실제 저장 전 확인할 후보로 표시합니다.

2024년 과거 제품 확인: 두 열무 열은 같은 3.2kg 제품으로 연결하면서 $20·$25 단가를 각각 보존합니다. 맛김치는 5kg이며, 오이김치는 무게 미확인(null)입니다. 과거 상품 키와 현재 판매 상품의 ID·용량을 구분합니다. 이 변경은 미리보기에만 적용됩니다.


## 그룹별 미리보기 검토

**엑셀 미리보기 → 그룹별 처리**에서 여러 그룹을 선택하거나 **모든 그룹 선택**으로 한 번에 기준을 반영합니다. 이는 검토 기준 저장이며 실제 고객·주문 가져오기는 아닙니다. 실제 원본에 대한 그룹은 사용자가 선택하기 전까지 자동 반영하지 않습니다.

- 주소 없음은 빈 값 보존, 과거 무게 미확인은 금액·개수 보존 및 kg 계산 제외, 같은 이름의 고객은 각각 보존하는 선택을 제공합니다.
- -$5와 그 외 음수 금액은 금액별로 나눕니다. 배달비 또는 별도 추가금으로 구분해도 최종 금액은 유지합니다. 의미가 불명확하면 보류합니다.
- 고객 연결 불명·금액 불일치·제품 수량 없는 행은 자동 합치기나 금액 덮어쓰기를 하지 않고 보류할 수 있습니다. 보류 고객의 연결 후보 주문도 함께 보류합니다.
- 보류는 삭제가 아닙니다. 보류 건수와 원본 행을 유지하며, 실제 가져오기에서는 제외해야 합니다. 연간 분석 합계에는 원본 전체 자료가 포함되므로 가져오기 대상 합계로 오해하지 않아야 합니다.
- 처리 방법에서 **적용 전 검토 상태로 되돌리기**를 선택하면 해당 그룹만 되돌릴 수 있습니다.
- 검토 기준은 원본 SHA-256 단위로 `.local/imports/review-*.json`에 공유 저장합니다. 같은 파일을 보는 두 사용자는 같은 기준을 사용합니다. 그룹 구성과 분석 기준이 바뀌면 재확인이 필요하며 화면 버전·파일 잠금으로 동시 덮어쓰기를 막습니다.
- 검토 기록에는 처리자·시각·최근 500회 변경 내역을 보존합니다. 원본 엑셀과 주문 DB는 변경하지 않습니다.

검증: `python3 tests/preview-groups.py`, `NODE_PATH="$PWD/.local/browser/node_modules" node tests/browser-groups.cjs`.

현재 제품 목록에는 사용자 요청으로 **포백5 · 백포기김치 5kg**을 추가했습니다. 기본가는 최신 첨부 엑셀 기준 $50이며 제품 관리에서 바꿀 수 있습니다. 과거 주문 단가 $45·$50은 각각 보존하고 현재 가격으로 다시 계산하지 않습니다.

사용자 설명에 따른 분류는 `app/excel-interpretation.php`에 분리했습니다. 최초 첨부 자료의 2행 제외, 개인/단체 고객·담당자, 단체 주문 연결, 실제 주문 연도, 김밥 기타 판매·동의받은 추가 수입을 다룹니다. 원본 총액과 김치 청구액을 구분하고 새 금액을 총액에 중복 가산하지 않습니다. 실제 가져오기에서도 고객 종류·소속·담당자와 기타 판매·추가 수입을 별도 저장합니다.


## 검토한 엑셀 실제 가져오기

[가져오기 실행 안내](docs/EXCEL_IMPORT.md)를 참고하세요. **엑셀 미리보기 → 실제 가져오기 → 저장할 내용 확인하기**에서 준비하며, 확인란과 실행 버튼을 누르기 전에는 업무 자료를 저장하지 않습니다. 원본 전체를 별도 시험 DB에서 검증했으며 개발 DB에는 최초 확인한 고객 193명·주문 946건을 가져왔습니다. 운영 서버 배포는 하지 않았습니다.

검증: `python tests/excel-import.py` (별도 DB 생성·정리), `NODE_PATH=/workspace/browser-check/node_modules node tests/browser-import.cjs` (준비 화면만 확인).


## 입금자 성명

고객 등록·수정의 **주로 입금하는 분 성명**과 입금 기록의 **이번 입금자 성명**을 구분합니다. 은행에 표시되는 영문 이름도 그대로 기록할 수 있으며, 기본 입금자 및 실제 입금 이력의 성명으로 고객을 검색합니다. 기본 이름 변경은 과거 입금 기록을 변경하지 않습니다. 입력하지 않은 성명은 미기록이며 기존 메모·닉네임에서 추정하지 않습니다. 금액·입금 완료 주문의 잠금 규칙은 유지합니다.


## Windows 직접 시험

[Windows 설치·10분 실습 안내](docs/WINDOWS_TEST.md)를 참고하세요. Docker Desktop이 실행 중이면 `windows-start.cmd`로 시작하고 `windows-stop.cmd`로 종료합니다. 새 설치는 빈 DB이며 클라우드 실제 고객·주문은 포함하지 않습니다. Windows에서 실행한 뒤 해당 컴퓨터의 `http://localhost:8080`을 엽니다. 실제 Windows에서 설치 검증은 아직 수행하지 않았습니다.

## 판매 통계

왼쪽 **판매 통계**에서 주간·월간·연간 및 기준 날짜를 선택합니다. 주문일 기준 김치 판매액(할인 후), 주문 수, 배달비, 기타 판매, 추가 수입, 현재 미입금을 나누어 확인합니다. 전년도 비교 기간을 표시하며 주간은 같은 요일의 52주 전을 사용합니다. 제품별 집계는 취소 수량·할인을 반영하고 과거 용량을 구분합니다. 실제 입금일 기준 금액은 별도로 표시하며 날짜 미기록 입금은 제외합니다. 이는 회계 결산이나 확정 생산 예측 기능은 아닙니다.

검증: `python tests/sales.py` (별도 시험 DB), `NODE_PATH=/workspace/browser-check/node_modules node tests/browser-sales.cjs` (읽기 전용 브라우저).

사용자 요청으로 최신 엑셀 비교 기능은 취소했습니다. 이후 소량의 추가 자료는 고객 등록·새 주문에서 입력합니다.


## 고객 기본값과 생산·재료 계산

[사용 안내 및 Codespaces 업데이트](docs/CUSTOMER_PRODUCTION.md)를 참고하세요. 이름 이외 고객 항목은 선택 사항이며, 지역 목록과 배달·픽업·교회 기본 수령 방법을 제공합니다. 고객 선택 시 수령 방법과 고객 메모를 새 주문에 복사하며 수정할 수 있습니다. 교회는 배달비가 없습니다. 전달 수량은 남은 수량을 기본값으로 표시합니다.

생산 화면은 체크한 주문의 전달 대기 수량과 선택 입력한 소매점 kg 물량으로 배추·무 소요량을 계산합니다. 배합·용량이 없으면 0으로 추정하지 않고 계산 가능한 부분만 표시합니다. 생산 완료 처리·재고 관리·소금·양념 계산과 도로 기준 배달 최적화는 아직 포함하지 않습니다. 유료 API는 사용하지 않습니다.

검증: `python tests/production.py`, `NODE_PATH=/workspace/browser-check/node_modules node tests/browser-preferences.cjs`.
